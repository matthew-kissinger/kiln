# Neutral runtime implementation receipt

Date: 2026-09-21. Scope: the bounded P03/P04/P05 runtime foundation approved in [the staged design](2026-09-21-neutral-runtime-design.md). This is implementation evidence, not completion of the entire category cutover or those three plan tasks.

## Implemented behavior

- `src/requirements-context.ts` strictly validates detached host binding snapshots, current/full semantic hashes, contiguous revision history and the effective requested-policy/advice hashes. No binding yields neutral empty requirements. Legacy `category`/`intent` execution inputs fail with `REQUIREMENTS_MIGRATION_REQUIRED` before source evaluation. Normal execution never invokes migration or manufactures a prop intent.
- `src/render.ts` runs universal and portable-material kernels through category-free inputs. Model `meta.category` is descriptive `meta.modelCategory`; generated requirements, intent, binding and claimed policy/advice hashes are removed from authoritative result metadata. The actual context is top-level `RenderResult.requirements`. Requirements provenance is not inserted into GLB bytes.
- `src/qa/requirements-applicability.ts` maps all **27** actual registered rules, preserving their current modes. Six universal kernels and the portable-material kernel run through the new adapter. Remaining domain checks have explicit `notRequested`/`notEvaluated` dispositions, never a hidden synthetic category.
- `src/qa/requirements-report.ts` emits report schema 2 with `requirementReadiness`, coverage, hashes and separate `accepted`/`incomplete`/`blocked` acceptance. Any requested field not covered by a qualified adapter makes acceptance incomplete. Disabling or demoting a mandatory kernel also prevents accepted status. Actual exact blockers remain blocked. Inferred/unknown statements do not become mandatory gates.
- Clip existence/targets and the explicit precomputed-tangent requirement use current kernels. Other requested fields remain visibly unevaluated, including fields partially overlapping a universal observation. This intentionally errs toward incomplete acceptance, rather than claiming a domain has been migrated because one measurement exists.
- `src/evaluator/protocol.ts` validates current reports against the transported binding and the original host request. Both the generic transport and `src/evaluator/subprocess.ts` reject a self-consistent result from another lineage. The subprocess also binds the response request ID and rejects legacy options before spawning. Isolated execution delegates to this boundary.
- `src/build-cache.ts` keys acceptance by separate policy/advice hashes while excluding labels, prose and lineage from semantic identity. A cache hit refreshes current provenance. Wrong-policy, corrupt or fabricated-acceptance entries become misses. A fresh evaluator response with another lineage fails before cache admission. Geometry bytes remain identical under different requirements; existing image/artifact cache keys were not changed.
- `src/requirements-context.ts` supplies a versioned source-reference checkpoint, whose decoder yields `host-binding-required`. `src/requirements-store.ts` now has an explicit host-only restore operation: validate the saved history, reject an occupied lineage, require restore authority, preserve historical revisions and append the current host decision. `src/requirements-identity.ts` holds the shared semantic binding hash without a store/validator import cycle.

`accepted` is acceptance against the declared requirements and currently mandatory kernels. It is not a visual score, a claim that every asset domain has been checked, or a substitute for importer/runtime qualification. Unrequested or unmeasured observations remain visible in rule/dimension coverage.

## TDD and verification

Observed focused red failures before the implementation covered source metadata authority/legacy options, policy-sensitive reuse, imported/forged report receipts, restore history, and subprocess request/lineage substitution. The final adversarial cache failures were wrong-policy reuse, fabricated accepted status, and relabeled fresh evaluator output. The final subprocess failures were foreign lineage, foreign request ID and legacy options reaching worker launch. Each passed after its bounded fix.

Final aggregate command:

```text
bun test src/contracts/requirements.test.ts src/requirements-store.test.ts src/requirements-context.test.ts src/qa/requirements-applicability.test.ts src/qa/requirements-report.test.ts src/qa/universal.test.ts src/qa/material.test.ts src/__tests__/neutral-render-runtime.test.ts src/__tests__/build-cache-requirements.test.ts src/__tests__/build-cache.test.ts src/__tests__/build-cache-admission.test.ts src/__tests__/geometry-gains.test.ts src/evaluator --timeout 20000
```

Result: **157 passed, 0 failed, 558 assertions across 24 files**, 11.62 seconds. The optional `build-cache-admission.test.ts` path matched no file and is not counted; the tested existing cache suite is `build-cache.test.ts`. Evidence includes actual subprocess transport, cancellation/pipe-order regressions, evaluator production-boundary tests, and the packaged Node worker fixture. That existing worker test rebuilds runtime bundles as part of its own setup; generated `dist/` changes are not a deployment.

`bun run typecheck` passed. Biome checked all 25 touched/new TypeScript files for this lane after formatting with no remaining errors. No live provider, commit, push or publication was performed. Full repository acceptance remains root's integrated gate after the remaining migrations.
