# Geometry, parts, and helper audit

Snapshot: 2026-09-21, source HEAD `b81cfd4caed64bd90547ff83b4e513e59a1d4913`. This is a read-only implementation audit plus offline probes. No engine behavior was changed. Evidence references below use repository-relative paths and one-based lines. The companion catalog census supplies symbol-by-symbol occurrence counts; occurrences are not proof of successful dogfooding.

## Assessment

The library already has a useful general-purpose geometry foundation. Its newest custom-mesh, deformation, sweep, semantic-frame, and CSG attribute-preservation work is appreciably more careful than its older convenience functions. The primary packaging risk is inconsistent composition semantics, rather than a shortage of primitives. A caller can confidently compose owned geometry through newer operations, then lose transforms, hierarchy, semantics, winding, or an expected opening through an older convenience helper.

Keep the low-level operations category agnostic. Keep domain scaffolds where they own a tested invariant, such as gable face frames or centered wheel pivots. Do not turn a gable shell into a universal architecture generator or a stylized gear into an engineering component. Discover these as optional construction recipes/capabilities. The existing implementation does not impose a general two-storey geometry limit: rooms, stairs, profiles, arrays and arbitrary meshes can build many floors or a coliseum. Category-specific contracts and prompts are a separate limitation investigated in the main report.

| P2 | Legacy room has a different floor datum | `src/primitives.ts:1032` promises floor top at ground but sets floor center to `+floorThickness/2`; direct probe with thickness .2 gives approximately `[0,.2]`. `src/architecture.ts:711` correctly sets center to `-floorThickness/2`. Mixing the two helpers creates a threshold/height mismatch. |
| P2 | Legacy room silently loses additional openings | `src/primitives.ts:1054` uses `find` for each wall even though the public option is an array of openings. Only the first opening on each wall survives. `createGableShell` filters and builds all openings. Reject unsupported multiplicity or migrate to a shared wall implementation. |
| P2 | Default shared-geometry ownership remains easy to violate | `src/primitives.ts:1668` memoizes primitive calls by JSON arguments within a sandbox; direct probe translating one `boxGeo(1,1,1)` changes the next identical call (same object, first vertex x=10.5). | P2 | Generic animation presets overwrite rest position | `src/primitives.ts:1424` and `1435` author absolute `[0,y,0]` tracks. `idleBreathing` on a torso rooted above ground erases its authored translation unless the user supplies an extra animation pivot. | P2 | Validation strength is uneven | `meshGeo`, deforms, sweeps and implicit surfaces validate dimensions/data deliberately; many base wrappers simply forward invalid numbers to Three.js. `wingGeo` accepts dimensions unchecked, `gearGeo` checks only a subset (`src/gears.ts:48`), `octaGridPlane` divides by unchecked tile counts (`src/primitives.ts:581`). | P2 | Shape-aware unwrap names exceed actual fallback behavior | `boxUnwrap` (`src/uv-shapes.ts:37`) keeps any existing UV attribute, regardless of whether it is box UVs; absent UVs get XY projection, which collapses side faces. `cylinderUnwrap` keeps any existing UVs and otherwise assumes origin-centered Y axis; its documented seam limitation is real. Expose preservation separately from true frame-aware reprojection. |
| P2 | Naming/material metrics are not robust semantic APIs | `getJointNames` matches only `Joint_`; new wheel spin pivots are named `WheelPivot_`. `validateAsset` always returns valid and uses unique material count as a draw-call proxy (`src/primitives.ts:1599`, `1623`). A scene can have one material and hundreds of draw calls. Advertise this as advisory metadata, not validation/performance certification. |

The P1 geometry/transform findings are independent of research trends and should precede catalog expansion. They survive the current focused passing tests. Two further bounded probes confirmed the input-validation gap: `createStairs` with `steps:1.5`, rise/run 3 creates two steps and bounds reaching X=4, Y=4; `octaGridPlane({tilesX:0,tilesY:1})` returns UVs containing NaN and Infinity rather than rejecting the invalid grid.

## Preset parts and reuse are three different things

1. Geometry/assembly factories include wings, wheels, ladders, rooms, gables, stairs, gears and blades. Their input/output contracts are inconsistent: geometry versus node versus record of nodes versus record with root/frame/socket metadata.
2. Character presets are semantic joint graphs and recipe text (`src/character.ts:669` onward). They do not supply a skinned mesh or animation controller. Treat them as scaffolds, not finished parts.
3. Material presets are versioned portable recipes (`src/material-recipes.ts:17` onward). They can remain a well-defined optional capability independent of asset category.

There is no evidence here that a new reusable-parts DSL is necessary. The existing ordinary-JavaScript trial demonstrates equal geometry/transforms and reduced source size for repeated portal frames, not model-success improvement: `docs/experiments/reusable-parts.md:1`, `scripts/experiment-reusable-parts.ts`, and the shipped `skills/kiln-author-asset/references/reusable-frame.kiln.js`. Build on that with common roots, attachment frames and mutation ownership, then measure real authoring tasks. `src/kit.ts` is GLB texture/material packaging, not a prefab library; the name should not be mistaken for geometry parts.

`BIPED_RIG_PRESET_V1` has 15 joint descriptors; `QUADRUPED_RIG_PRESET_V1` has 16 (`src/character.ts:669-744`). `expandCharacterRigPreset` clones either semantic graph. These distinctions preserve an accurate inventory of what users can actually invoke.

## Evidence and verification

Executed offline with Bun 1.4.2 and `KILN_RENDER=cpu`: `bun test --timeout 20000` against `primitives`, `geometry-authoring`, `deform`, `sweep`, `implicit`, `profile`, `vehicle`, `architecture`, `gears`, `ops`, and `uv-shapes` test files in `src/__tests__`. Result: **194 pass, 0 fail, 6,587 assertions across 11 files**. This is a focused gate, not the complete repository suite or a package release gate.

Direct ephemeral `bun -e` probes measured signed wing volume, radial/mirror transforms, legacy room floor bounds, sandbox primitive sharing, absolute breathing-track values, snapTo under stale ancestors, fractional stair count and zero atlas tile count. Those probes were not added as production tests and did not mutate source. Their numeric results appear above.

Existing tests provide unusually useful structural evidence for new capabilities: profile volume/holes/axis/GLB interop; custom geometry periodic seams and Float32 bounds; deform ownership and local frames; closed sweeps and transport; implicit budgets/determinism; transformed vehicle socket assemblies; gable face frames and enterable shell. None substitutes for randomized composition, single-sided visual inspection, or frontier-model usability measurements. The current 194-test pass alongside the demonstrated wing and transform bugs is direct evidence of missing adversarial composition coverage.

Useful additional checked-in test evidence (not rerun here): `csg-preservation.test.ts`, `csg-uv-integrity.test.ts`, `geometry-export-contract.test.ts`, `geometry-export.test.ts`, `geometry-policy-runtime.test.ts`, `billboard-primitives.test.ts`, `animation-textured.test.ts`, `character.test.ts`, `instancing.test.ts`, `architecture-expansion-gate.test.ts`, and procedural/material tests. The architecture expansion gate explicitly records a negative result for fixed shed/hip candidates; read that before adding roof presets just because they sound useful.

## Recommended next tasks

1. Before packaging, reproduce the P1 geometry/transform failures in permanent focused tests and fix them with explicit transform composition and ancestor refresh. Add a whole-assembly reuse decision: either a separate operation or an honest mesh-only name. Preserve source geometry/material sharing without deleting subtree structure or semantic identity.
2. Reconcile room/opening/floor semantics and deprecated copy naming. Remove misleading comments that say clone-before-mutation when clone is identity. Carry the selected ownership rule through direct module and sandbox use.
3. Define a small contract table attached to every discoverable helper: return kind, ownership, async, units/axes, coordinate space, topology promise, UV/material/provenance preservation, semantic effects, cost bound, maturity. This metadata is more valuable than another broad category switch.
4. Make geometry-first operations composable with optional frame/socket-aware assemblies. Add general attachment-frame mating only if needed after validating existing semantic socket consumption; do not hard-code a vehicle-only attachment architecture into all assets.
5. Build a composition matrix covering reflected/scaled/rotated parents, repeated hierarchy, texture seams, UV-preserving booleans, deform-after-sweep, subdivision-after-CSG, exported normals/winding, and exact source-to-GLB dimensions. Use metamorphic properties (rotation/scale equivariance, copy independence, array preservation) instead of only snapshots and triangle counts.
6. Dogfood narrow representative tasks with held-out prompts: 3-storey facade with repeated arched openings; coliseum annulus with tiered seating and entrances; nonuniformly scaled radial columns; vehicle with reused custom wheel geometry; articulated non-humanoid; foliage with export-portable cutouts; directional-textured swept rail; tiny mechanical asset. Measure successful export, repairs, tool discovery, semantic correctness and blinded visual assessment separately.
7. Add new helpers only when a measured repeated failure cannot be solved with a clearer existing operation/recipe. Plausible candidates to evaluate are generic wall-with-multiple-openings, frame-aware extrusion/attachment, segmented primitive controls, planar/cylindrical UV projection with explicit frames, and hierarchy-preserving repetition. General beveling, remeshing, arbitrary profile correspondence and robust self-intersection checks are substantial geometry features, not small convenience helpers.

The right unification is common contracts and discovery, not one giant function. Surface revolution and solid revolution, a reusable mesh and an articulated assembly, a bounding-box snap and a mating socket each represent real distinctions that should remain visible.
